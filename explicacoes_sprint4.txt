1. OBJETIVO
Construir e comparar dois modelos supervisionados para classificar o nível de engajamento (baixo, medio, alto) dos usuários do SoulIA a partir dos atributos comportamentais da base da Sprint 3.

2. ORIGEM E CARACTERÍSTICAS DOS DADOS
Foi utilizada a base_soulia.csv da Sprint 3: 500 registros sintéticos, 15 colunas. Cada linha representa um usuário simulado. A coluna id_usuario é identificadora e não é utilizada no treinamento. O alvo é nivel_engajamento. Foram usadas 13 variáveis: idade e 12 indicadores de uso/participação.

3. MODELOS IMPLEMENTADOS
Modelo 1: Decision Tree (Árvore de Decisão), com profundidade máxima 5, mínimo de 4 amostras por folha e ponderação de classes. Escolha: modelo interpretável, que permite visualizar regras de classificação.
Modelo 2: Random Forest, com 300 árvores, mínimo de 2 amostras por folha e ponderação balanceada por amostra. Escolha: combinação de árvores para reduzir a variabilidade de uma árvore isolada.

4. METODOLOGIA
Divisão estratificada em 80% treino e 20% teste, com random_state=42. Métricas: acurácia, precisão macro, recall macro e F1 macro. Também foi incluída validação cruzada estratificada de 5 partes no conjunto de treino (F1 macro), sem usar o conjunto de teste. O notebook contém os relatórios por classe, matrizes de confusão e importância das variáveis.

Leitura dos resultados: os dois modelos acertaram 93% (árvore) e 94% (floresta) no teste. Todos os erros ocorreram entre classes vizinhas (baixo/medio e medio/alto); nenhum modelo confundiu baixo com alto. A classe alto, minoritária, é a mais difícil: recall de 0,80 na árvore (4 de 5 usuários) e 0,60 na floresta (3 de 5). Como o teste tem apenas 5 usuários alto, um único acerto muda o recall em 20 pontos percentuais. O teste e a validação cruzada apontam vencedores diferentes, então os dois modelos devem ser considerados de desempenho parecido, sem um claramente superior. Também observamos que uma das folhas da árvore usa a idade para separar medio de alto, o que provavelmente é ruído causado pelos poucos exemplos da classe alto no treino (19).

6. JUSTIFICATIVA DO MODELO DISPONIBILIZADO
A API disponibiliza a Decision Tree. É importante ser claro sobre o motivo: não afirmamos que ela tenha desempenho superior. No teste, a árvore teve F1 macro maior (0,8915 contra 0,8580), mas essa diferença equivale a um único usuário da classe alto (4 acertos contra 3), e a validação cruzada favorece a Random Forest (0,8535 contra 0,7895). Por isso, a escolha se apoia principalmente em interpretabilidade e simplicidade: as regras da árvore podem ser lidas e explicadas (por exemplo, a classe alto exige muitos pontos e muitas interações com o chatbot), o que é importante para justificar sugestões ao usuário, e o arquivo do modelo é pequeno e leve para a API. O custo dessa decisão é uma possível menor estabilidade. Se o objetivo passar a ser maximizar o desempenho, a Random Forest é a candidata natural; a API usa apenas o objeto model e a lista de variáveis do arquivo .joblib, então a troca exige apenas salvar o outro modelo no mesmo formato. A comparação completa está no notebook.

7. API REST
Tecnologia: FastAPI. Endpoint GET /health para verificação e POST /predict para receber os 13 atributos e retornar nivel_engajamento, modelo e probabilidades. Documentação automática em /docs. A API valida os dados de entrada: todos os 13 campos são obrigatórios, idade entre 13 e 100, demais valores não negativos, missoes_concluidas não pode ser maior que missoes_recebidas e streak_maximo não pode ser maior que dias_ativo (as mesmas regras de qualidade validadas na base); entradas inválidas retornam erro 422. Instruções e exemplo de requisição estão em README_API.txt.

8. LIMITAÇÕES E CUIDADOS
Os dados são sintéticos e a classe alto é minoritária (24 de 500 registros; 5 no conjunto de teste). Como os rótulos foram definidos na geração da base, os modelos podem aprender as regras artificiais utilizadas, e a importância das variáveis provavelmente reflete essas regras. O conjunto de teste é pequeno (100 registros), e as diferenças entre os modelos estão dentro da margem de ruído. As probabilidades da árvore são frequentemente 0 ou 1 (folhas puras) e não representam confiança calibrada. As métricas não devem ser interpretadas como desempenho comprovado em usuários reais. A API é demonstrativa; antes de produção, usar autenticação, monitoramento, proteção de dados e reavaliação com dados reais. A previsão não deve ser tratada como avaliação definitiva do usuário.
Próximos passos: coletar dados reais com consentimento, aumentar os exemplos da classe alto, repetir a validação cruzada para uma comparação mais estável, ajustar hiperparâmetros e calibrar as probabilidades.

SOULIA - API REST DE MACHINE LEARNING

1) Instale Python 3.11 ou superior (exigido pelo scikit-learn 1.8.0, versao usada para salvar o modelo).
2) Abra o terminal nesta pasta.
3) (Opcional, recomendado) Crie ambiente virtual: python -m venv .venv
   Windows: .venv\Scripts\activate
   macOS/Linux: source .venv/bin/activate
4) Instale: pip install -r requirements.txt
5) Inicie: uvicorn api:app --reload --host 127.0.0.1 --port 8000
6) Documentacao interativa: http://127.0.0.1:8000/docs
7) Verifique: GET http://127.0.0.1:8000/health
8) Previsao: POST http://127.0.0.1:8000/predict

Exemplo de JSON para POST /predict:
{
  "idade": 27, "dias_ativo": 120, "acessos": 130,
  "missoes_recebidas": 45, "missoes_concluidas": 24,
  "acoes_sustentaveis": 25, "interacoes_chatbot": 100,
  "comentarios": 20, "curtidas": 80,
  "participacoes_comunidade": 8, "streak_maximo": 40,
  "pontos": 1800, "recompensas_resgatadas": 4
}
